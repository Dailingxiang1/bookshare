先开通账号，按这个顺序

1. Azure 学生订阅

访问 Azure for Students 官方入口，用你自己的 Microsoft 账号登录，按页面要求完成学生身份验证。Microsoft 当前说明提供 100 美元额度、有效期 12 个月，无需信用卡，具体资格以验证页面为准。

登录 Azure Portal，进入“订阅”，确认能看到已启用的学生订阅。如果学生认证无法通过，先询问任课老师是否提供教学订阅或实验账号。暂时不用购买付费订阅。

2. 免费 GitHub 账号与仓库

在 GitHub 注册自己的账号，创建一个 bookshare 仓库。当前目标为 Dailingxiang1/bookshare。仓库根目录放本项目的 package.json、web、server 和 azure-pipelines.yml 等文件。保留 .gitignore，不要上传 .local、node_modules 或云端密钥。

3. Azure DevOps 组织与项目

访问 Azure DevOps，使用 Azure 所用的 Microsoft 账号登录，创建一个组织和一个项目（例如 BookShare）。按当前 Microsoft 流程，新建组织需要有效 Azure 订阅；学生订阅可用于创建组织。参考 创建组织 和 订阅资格说明。

在组织设置的 Billing 中连接学生订阅，按页面启用免费托管并行作业额度。是否已获额度以组织实际显示为准；没有额度时先按学校说明处理，不要直接购买并行作业。官方说明：并行作业与免费额度。

上述账号注册、密码设置、验证码和学生验证由你在官方页面自行完成。无需把密码、验证码或完整密钥发给任何人。

现在就能使用本地网页

在项目目录执行以下命令，保持终端开启，然后打开 本机 BookShare 网页。需要 Node.js 22.13 或更高版本。

npm ci
npm start

网页可上传 PDF / PNG / JPEG，进行搜索、分类、排序、预览、下载、修改及删除。PDF 使用本地打包的 Mozilla PDF.js 渲染，支持翻页。首次启动生成三份原创示例笔记。数据放在 .local，不会上传到外部服务。

本机页面明确显示“本机演示”。未配置 Azure Translator 时，翻译按钮禁用。没有使用伪造译文或假云端数据。

npm run check
npm test
npm run test:ci
npm run build

构建产物位于 dist，包括四个网页入口文件和本地 PDF.js 资源。reports/junit.xml 是本机测试结果，不能替代实际 Azure DevOps 的成功运行记录。

当前部署与分阶段脚本

这次已在 Azure for Students 的 bookshare-coursework 资源组完成部署，实际资源位于 francecentral。资源组元数据位置为 East US，与各资源实际位置独立。以下为复现和维护步骤；当前部署继续使用已有资源。

A. 选择订阅、区域与预算

az login
az account show
az account set --subscription YOUR_SUBSCRIPTION_ID

选择该学生订阅实际允许的区域，资源组使用项目专用名称，例如 bookshare-coursework。模板使用 Standard LRS Storage、Cosmos NoSQL serverless、Windows Consumption Function 和 Translator F0。F0 已占用时会失败，不会自动切换到收费 S1。消费型资源仍可能消耗学生额度，应在 Cost Management 中设置资源组预算提醒。

B. 部署基础资源

# 本次学生订阅允许 francecentral；其他订阅应先核对实际区域策略
./scripts/Deploy-Resources.ps1 -ResourceGroup bookshare-coursework -Location francecentral -Apply

# 资源组已经存在时，可先进行 Validate / what-if
./scripts/Deploy-Resources.ps1 -ResourceGroup bookshare-coursework -Location francecentral

模板 infra/main.json 创建私有 assets 容器、Cosmos bookshare/assets（NoSQL API，分区键 /id）、Function 及 Translator。订阅服务策略造成失败时，应查看明确报错后调整区域或申请课程资源，不要换成 MongoDB API。

C–D. Cloud Shell 连接与六条工作流

在 Cloud Shell（PowerShell）上传交付目录中的 BookShare_CloudShell_v3.zip，解压到 $HOME/bookshare-deploy。脚本会从已有成功部署读取资源信息，读取实际 Connector 认证元数据，以 export=true 导出真实 Swagger，再生成连接与工作流。

Expand-Archive -LiteralPath "$HOME/BookShare_CloudShell_v3.zip" -DestinationPath "$HOME/bookshare-deploy" -Force
& "$HOME/bookshare-deploy/scripts/Deploy-CloudShell.ps1" -Stage Workflows -Apply

当前两个连接已为 Connected，IUPS、RAI、RIPS、UIPS、DIPS、FIPS 全部为 Enabled / Succeeded。全部云端 CRUD 由 Logic Apps 完成，Function 调用签名回调。连接密钥由 Azure 的 listKeys 表达式解析。

E. 发布与真实检查

& "$HOME/bookshare-deploy/scripts/Deploy-CloudShell.ps1" -Stage Publish -Apply
& "$HOME/bookshare-deploy/scripts/Deploy-CloudShell.ps1" -Stage Verify -Apply

发布脚本将基础回调地址与 relativePath 合并，保留原签名查询串；然后配置 Function、Translator、网站精确 Origin 并发布代码。Verify 已在当前 Azure 部署通过 15 项检查，使用并清除自己的临时 PDF；检查报告位于 Cloud Shell 的 $HOME/bookshare-deploy/reports/cloud-smoke.json。

管理口令保存在 Cloud Shell 的 $HOME/bookshare-deploy/.local/cloud/organiser-token.local.txt。在网页“管理入口”输入该口令即可写入。口令、密钥和签名回调保留在 Function 配置与忽略的本地目录中。测试后的空目录属于正常状态，演示时请上传原创资料。

F. GitHub 连接 Azure DevOps Pipeline

  1. 把本项目源码提交到自己的 GitHub 仓库。仓库根目录必须包含 azure-pipelines.yml。
  2. Azure DevOps 项目进入 Pipelines → New pipeline → GitHub，按页面授权该仓库。
  3. 选择 Existing Azure Pipelines YAML file，选择 /azure-pipelines.yml，保存并运行。
  4. 确认 Node 安装、npm ci、语法检查、测试、前端构建均成功，能下载 bookshare-frontend 产物。
  5. 保存实际运行页面和对应 GitHub commit。只有 YAML 文件、静态截图或本机 npm build 均不能证明流水线已工作。

课程要求的核心是 GitHub 到 Azure DevOps 的实际前端构建。自动部署可作为后续扩展，不必为了完成基本项额外购买服务。

实现边界与后续改进

每份文件不超过 5 MiB。当前列表以 100 条 Connector 页面为目标，最多跟进 20 页，超过上限返回明确错误。大型目录需要游标分页和服务器搜索。修改仅更新元数据，文件替换通过新建资料完成。Blob 和 Cosmos 没有跨服务事务，失败的回滚或删除需要检查工作流并清理孤立文件。共享口令适合小型演示，正式多用户系统应增加身份、角色、审核和病毒扫描。
